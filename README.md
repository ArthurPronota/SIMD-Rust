# SIMD в Rust: основные подходы

## 🧩 Что такое SIMD

**SIMD (Single Instruction, Multiple Data)** — параллелизм на уровне данных: одна процессорная инструкция одновременно выполняется над несколькими элементами, упакованными в один регистр.

**SIMD-регистры** — специальные аппаратные регистры процессора, хранящие не одно значение, а вектор из нескольких значений (чисел с плавающей точкой или целых) одновременно.

Ширина регистра определяет, сколько элементов обрабатывается за раз:

| Регистр | Ширина | `f32` за раз | `i32` за раз | Технология |
|---------|--------|--------------|--------------|------------|
| `xmm` | 128 бит | 4 | 4 | SSE |
| `ymm` | 256 бит | 8 | 8 | AVX / AVX2 |
| `zmm` | 512 бит | 16 | 16 | AVX-512 |
| NEON | 128 бит | 4 | 4 | ARM |

Ускорение — **4–8 раз** (иногда до 16 на AVX-512) на подходящих задачах.

## 🎯 Три основных подхода

### 1️⃣ Авто-векторизация LLVM (ничего не делаем руками)

**LLVM** (Low Level Virtual Machine — низкоуровневая виртуальная машина) — инфраструктура для разработки компиляторов, используется в Rust для генерации машинного кода.

При включённой оптимизации (`-C opt-level=3` или `-C target-cpu=native`) LLVM:
- Распознаёт паттерн (например, редукцию — накопление суммы),
- Разворачивает цикл и группирует операции,
- Загружает несколько чисел за раз в SIMD-регистры,
- Применяет **вертикальное** сложение (`vaddps`), а затем **горизонтальное** (`haddps`) для сведения результата.

**Пример, который LLVM обычно векторизует сам:**

```rust
#[unsafe(no_mangle)]
#[inline(never)]
pub fn add_arrays(a: &[f32], b: &[f32], out: &mut [f32]) {
    assert_eq!(a.len(), b.len());
    assert_eq!(a.len(), out.len());

    for i in 0..a.len() {
        out[i] = a[i] + b[i];
    }
}
```

**Плюсы:** ничего не пишем, безопасно, переносимо.
**Минусы:** LLVM может не распознать паттерн; результат непредсказуем.

### 2️⃣ `std::simd` (portable SIMD, nightly)

Портативный API для SIMD, не привязанный к архитектуре. Требует **nightly** (`#![feature(portable_simd)]`).

```rust
#![feature(portable_simd)]
use std::simd::f32x8;

pub fn sum_simd(xs: &[f32]) -> f32 {
    let mut acc = f32x8::splat(0.0);
    let chunks = xs.chunks_exact(8);
    let rem = chunks.remainder();

    for chunk in chunks {
        let v = f32x8::from_slice(chunk);
        acc += v;             // вертикальное сложение: 8 сумм параллельно
    }

    let mut total = acc.reduce_sum();  // горизонтальное сложение: 8 → 1
    for &x in rem {
        total += x;           // хвост — скалярно
    }
    total
}
```

**Ключевые моменты:**
- `f32x8` — вектор из 8 `f32` (один регистр `ymm`).
- `acc += v` — **вертикальное** сложение (8 сумм параллельно).
- `reduce_sum()` — **горизонтальное** сложение (8 значений → 1).
- `remainder` — хвост обрабатывается скалярно.

**Плюсы:** портативно, читаемо.
**Минусы:** nightly, API не стабилен.

---

### 3️⃣ `std::arch` (intrinsics, stable)

Прямой доступ к инструкциям процессора. Работает на **stable**, но требует `unsafe` и платформо-специфичен.

```rust
#[cfg(target_arch = "x86_64")]
use std::arch::x86_64::*;

#[cfg(target_arch = "x86_64")]
#[target_feature(enable = "avx2")]
pub unsafe fn sum_avx2(xs: &[f32]) -> f32 {
    let mut acc = _mm256_setzero_ps();
    let len = xs.len();
    let mut i = 0;

    while i + 8 <= len {
        let v = _mm256_loadu_ps(xs.as_ptr().add(i));
        acc = _mm256_add_ps(acc, v);
        i += 8;
    }

    let mut buf = [0.0f32; 8];
    _mm256_storeu_ps(buf.as_mut_ptr(), acc);
    let mut total = buf.iter().sum::<f32>();

    while i < len {
        total += xs[i];
        i += 1;
    }
    total
}

pub fn sum_simd_dispatch(xs: &[f32]) -> f32 {
    #[cfg(target_arch = "x86_64")]
    {
        if is_x86_feature_detected!("avx2") {
            return unsafe { sum_avx2(xs) };
        }
    }
    xs.iter().sum()   // fallback
}
```

**Ключевые моменты:**
- `#[target_feature(enable = "avx2")]` — компилятор знает, что здесь можно AVX2.
- `_mm256_setzero_ps` — 8 нулей в одном регистре.
- `_mm256_loadu_ps` — загрузка **unaligned** (без требований к выравниванию).
- `_mm256_add_ps` — вертикальное сложение.
- `is_x86_feature_detected!("avx2")` — рантайм-проверка + скалярный fallback.

**Плюсы:** полный контроль, stable, максимум скорости.
**Минусы:** `unsafe`, платформозависимо, нужен fallback.

## 🔄 Сравнение подходов

| Подход | Плюсы | Минусы |
|--------|-------|--------|
| **Авто-векторизация** | Ничего не пишем, безопасно, работает везде | LLVM может не распознать паттерн |
| **`std::simd`** | Портативно, читаемо | Nightly, API не стабилен |
| **`std::arch`** | Полный контроль, stable, максимум скорости | `unsafe`, платформозависимо, нужен fallback |

## ⚙️ Настройка проекта

### `.cargo/config.toml` — разрешает инструкции CPU

⚠️ Файл **обязан** лежать в `.cargo/config.toml`, а не рядом с `Cargo.toml`:

```
o_074/
├── .cargo/
│   └── config.toml   ← правильно
├── Cargo.toml
└── src/main.rs
```

```toml
[build]
rustflags = ["-C", "target-cpu=native"]
```

**Что делает `-C target-cpu=native`:**
- Определяет модель текущего CPU и разрешает все его инструкции (AVX2, AVX-512, FMA, BMI, AES-NI).
- Бинарник становится **непереносимым** — на старом CPU упадёт с `SIGILL`.

⚠️ `.cargo/config.toml` **лишь разрешает** инструкции процессора, но **не гарантирует** SIMD. Векторизация зависит от LLVM и паттерна кода.

⚠️ Если задан `RUSTFLAGS` в окружении — `[build] rustflags` **игнорируется** (переменная приоритетнее).

## 🔍 Проверка: применился ли SIMD

### Способ 1: `cargo rustc -- --emit=asm`

```powershell
cargo rustc --release -- --emit=asm
Select-String -Path target\release\deps\*.s -Pattern "add_arrays:" -Context 0,80
```

| Инструкция | Что означает |
|------------|--------------|
| `vaddps ymm` | ✅ Сложение 8 `f32` (AVX) — SIMD |
| `vaddps xmm` | ✅ Сложение 4 `f32` (SSE) — SIMD |
| `addss` / `vaddss` | ❌ Сложение одного `f32` — **не** векторизация |
| `vmovups` | Загрузка 8 `f32` без выравнивания |
| `haddps` | Горизонтальное сложение |
| `ymm0`, `ymm1`... | 256-битные SIMD-регистры |

### Способ 2: `cargo-show-asm`

```bash
cargo install cargo-show-asm
cargo asm --rust o_074::add_arrays
```

Показывает ассемблер **конкретной функции** без ручного поиска.

### Способ 3: Godbolt

[godbolt.org](https://godbolt.org) — Rust, флаги `-C opt-level=3 -C target-cpu=native`. Сразу видно ассемблер с подсветкой соответствия исходнику.

## 📖 Разбор AT&T-синтаксиса (пример `add_arrays`)

```asm
vmovups (%rcx,%rsi), %ymm0      ; загрузка a[i..i+8]
vmovups 32(%rcx,%rsi), %ymm1    ; загрузка a[i+8..i+16]
vmovups 64(%rcx,%rsi), %ymm2    ; загрузка a[i+16..i+24]
vmovups 96(%rcx,%rsi), %ymm3    ; загрузка a[i+24..i+32]

vaddps (%r8,%rsi), %ymm0, %ymm0 ; ymm0 = ymm0 + b[i..i+8]
vaddps 32(%r8,%rsi), %ymm1, %ymm1
vaddps 64(%r8,%rsi), %ymm2, %ymm2
vaddps 96(%r8,%rsi), %ymm3, %ymm3
```

**Синтаксис:** `инструкция источник, назначение`.

**Обозначения:**
- `%rcx` — адрес массива `a`.
- `%r8` — адрес массива `b`.
- `%rsi` — текущее смещение в байтах.
- `%ymm0–%ymm3` — 256-битные SIMD-регистры (по 8 `f32`).
- `32`, `64`, `96` — смещения в байтах.
- `vmovups` — загрузка **не обязательно выровненных** данных.
- `vaddps` — параллельное сложение упакованных `f32`.
- Адрес = `rcx + rsi + смещение`.

Эквивалент на Rust:
```rust
for j in 0..32 {
    result[i + j] = a[i + j] + b[i + j];
}
```
Но SIMD делает это **четырьмя** векторными сложениями по 8 чисел вместо 32 скалярных.

## ⚠️ Почему сумма (`my_sum`) может не векторизоваться

```rust
fn my_sum(a: &[f32]) -> f32 {
    let mut sum = 0.0;
    for &v in a {
        sum += v;
    }
    sum
}
```

**Причина:** SIMD-суммирование **меняет порядок операций**, а значит может изменить результат из-за округления `f32`. LLVM по умолчанию **консервативен** и не делает этого без явного разрешения (fast-math флаги).

**В отличие от поэлементного сложения** (`out[i] = a[i] + b[i]`) — там порядок не меняется, и компилятору проще безопасно векторизовать.

**Решение:** явные intrinsics (`std::arch`) или portable SIMD (`std::simd`).

## 🧪 Практический вывод

1. **Сначала пишите обычный цикл** и собирайте с `-C opt-level=3 -C target-cpu=native`.
2. **Проверьте ассемблер** (`cargo rustc -- --emit=asm` или godbolt) — есть ли SIMD-инструкции.
3. **Если нет** — попробуйте переписать цикл так, чтобы LLVM было проще:
   - убрать ветвления,
   - `chunks_exact(8)`,
   - локальные аккумуляторы,
   - избегать алиасинга.
4. **Если всё равно нет** — берите `std::simd` (nightly, портативно) или `std::arch` (stable, максимум контроля).
5. **Всегда замеряйте** — SIMD не всегда быстрее: на маленьких массивах накладные расходы на горизонтальное сложение и диспатч могут съесть выигрыш.

---

## 🎯 Итог

> **LLVM на release с `-C target-cpu=native` такой код почти всегда векторизует. Сначала имеет смысл проверить это, а уже потом писать руками.**

Порядок действий:
1. Обычный цикл + `target-cpu=native` → проверка ассемблера.
2. Если SIMD нет — упростить паттерн для LLVM.
3. Если всё ещё нет — `std::simd` или `std::arch`.
4. Замерить эффект (`Instant::now()`, `criterion`).
